1. En önemli kural: Token budget = context window değil

Mesela modelin 32K context'i varsa:

32K'nın tamamını doldurmaya çalışma.

Örneğin:

Model context capacity: 32K

Reserved budget
────────────────────────
System / Agent rules       2K
Project memory             2K
Conversation                4K
Relevant source            12K
Tool results                4K
Attachments                 2K
Response reserve            6K
────────────────────────
Total                      32K

Ama ben bunu sabit rakamlarla kodlamam.

Şöyle yaparım:

max_context_tokens
output_reserve_tokens
safety_margin_tokens

Model değişince:

Gemma → farklı budget
Qwen  → farklı budget
Cloud → provider limitine göre

Context Manager bunları otomatik hesaplar.

3. Dosya seçimini Context Manager yapmalı

Burası bence RAG'siz sistemimizin kalbi.

Kullanıcı:

ProjectManager'daki create_project fonksiyonunu düzelt.

dedi.

Agent bütün repository'yi istememeli.

Önce:

project_manager.rs

sonra gerekiyorsa:

filesystem.rs
project.rs
error.rs

gibi dependency/context ilişkili dosyaları getirir.

Öncelik sırası mesela:

1. User selected code
2. Currently open file
3. Directly referenced files
4. Imported/dependent files
5. Recently modified files
6. Project memory
7. Search results
8. Other files

Ve budget dolduğunda düşük öncelikliler çıkar.

Bu RAG değil.

Bu daha basit bir context selection / relevance system.

4. Her dosyanın tamamını da göndermeyelim

Örneğin:

ile uğraşıyorsun.

ilgili struct

“filesystem.rs'deki create_dir implementasyonunu da görmem lazım.”

der ve tool ile onu ister.

Context on-demand büyüsün.

Bu çok önemli.

8. Context'e bir "source" sistemi koyardım

Bu çok işimize yarar:

ContextItem {
    source: User | File | Memory | Tool | Conversation | Attachment,
    priority: u8,
    tokens: usize,
    content: ...
}

Örneğin:

user-selected-code      priority 100
current-file            priority 90
direct-dependency       priority 80
memory                  priority 70
conversation            priority 60
terminal-output         priority 50

Budget aşılırsa:

sort by priority
↓
keep highest value items
↓
drop/truncate lower value items

Böylece Context Manager “ne göndereceğim?” sorusuna sistematik cevap verir.

9. Mac OOM konusunda en kritik ayrım

Burada küçük ama önemli bir düzeltme yapayım:

Token budget'i kısmak Mac RAM'ini birebir aynı oranda düşürmez.

Local LLM'de özellikle KV cache önemli.

Kabaca:

Model weights
+
KV cache
+
runtime memory
+
context
+
application

toplam RAM baskısını oluşturur.

Dolayısıyla Forge'un görevi sadece:

“20K token gönderme.”

değil.

Aynı zamanda:

“Context'i gereksiz yere büyütme.”

olmalı.

Özellikle agent uzun süre çalışırken context'in sürekli büyümesini engellemek önemli.
